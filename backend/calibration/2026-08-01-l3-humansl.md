## 1. 命令与执行摘要

```bash
# 冒烟（9 路分先 1 盘，本地 540v 执黑，Human-SL rank_1k 执白）
POST /api/v1/engine/calibrate {"model_a":"b11c768h12","visits_a":540,"human_sl_model":"b18c384nbt-humanv0.bin.gz",
                               "human_sl_side":"b","human_sl_profile":"rank_1k","size":9,"komi":7.5,"games":1,"black_side":"a"}
→ B+R（108 手，Human-SL 中盘认输）

# 9 路全档扫描（rank_1k）：5 档 × 让 0~3 子 × 2 盘 = 40 盘
python backend/scripts/calibrate.py --api http://127.0.0.1:8765/api/v1 \
    --plan b11c768h12 --levels am5k am1k am1d am3d am6d \
    --human-sl b18c384nbt-humanv0.bin.gz --human-sl-side b \
    --human-sl-profile rank_1k --games 2 --size 9 --scan 3

# 19 路验证（rank_1k 让 0~3 / 让 7；rank_1d/rank_3d/rank_9d 分先）
python backend/scripts/calibrate.py --api http://127.0.0.1:8765/api/v1 \
    --plan b11c768h12 --levels am1d \
    --human-sl b18c384nbt-humanv0.bin.gz --human-sl-side b \
    --human-sl-profile rank_1k --games 2 --size 19 --scan 3
python backend/scripts/calibrate.py --api http://127.0.0.1:8765/api/v1 \
    --model-a b11c768h12 --model-b b11c768h12 --visits-a 540 --visits-b 0 \
    --human-sl b18c384nbt-humanv0.bin.gz --human-sl-side b \
    --human-sl-profile rank_3d --handicap 0 --games 2 --size 19   # 及 rank_1d / rank_9d / visits-a 130 等变体
```

- 环境：KataGo v1.17.0 · RTX 3060 Laptop · b11c768h12 ≈ 1900 visits/s
- Human-SL 配置：`backend/katago/human_calib.cfg`（模板）→ 每 profile 生成 `human_calib_<profile>.cfg`
  - `humanSLProfile=rank_1k/1d/3d`（逐档切换）· `humanSLChosenMoveProp=1.0`（纯风格模仿）·
    `humanSLChosenMoveIgnorePass=true` · `humanSLChosenMovePiklLambda=100000000`
  - `maxVisits=200`（搜索仅用于 pass/resign 判断）· `resignThreshold=-0.5`、`resignConsecTurns=10`
    （校准场景放宽：resign 阈值不影响选点棋力、只决定认输时机，防止大败方死扛满盘）
- 让子约定：本地引擎执黑摆子（弱方执黑），Human-SL 执白；分先档（让 0）按标准贴目 7.5，
  让子档（≥1）不贴目（9 路 komi=0 时黑先手优势约 7 目，分先档不贴目会变成「黑必胜」）。

## 4. Human-SL 精度局限标注（重要）

1. **风格模仿 ≠ 强度标定（官方声明）**：Human-SL 的段位标签是「模仿目标」而非「实测棋力」。
   README 4.2 已警示；本次实测确认偏差比预期更大——`humanSLChosenMoveProp=1.0` 时选点 100% 服从
   人类落子分布（无搜索修正），棋力上限即人类分布的统计倾向，KataGo 引擎（哪怕 130 visits 搜索）
   即可稳定抓住其随手棋，73~105 手内令其认输。
2. **9 路严重不适配**：b18c384nbt-humanv0 按 19 路人类棋谱训练，9 路小棋盘上人类分布失真，
   Human-SL 19~48 手即崩盘认输，9 路数据完全无区分度（已转 19 路验证）。
3. **高段位仅方向参考**：rank_9d 分先（贴 7.5）仍不敌 130v 引擎，说明纯 policy 模式下
   「人类高手风格」与「高手实力」是两回事——风格分布的 argmax 是统计众数，不含人类高手
   的计算与判断深度。
4. sanity check：直接 GTP 下 10 手（rank_9d），选点（C17/Q4/O17 等）全部为合理人类布局，
   **排除实现 bug**——是数据源（Human-SL 权重特性）本身决定的棋力上限。

## 5. BASE_VISITS_AM1D 建议值

任务预设的推断路径是「若本地 am1d(540v) 与 rank_1k 均势 → 当前 540v ≈ 1 级（偏弱）→ BASE 上调
2~4 倍」。**实测方向完全相反**：540v 让 rank_1k 7 子（19 路）仍全胜，130v 都分先胜 rank_3d/rank_9d。
因此不存在「540v ≈ rank_1k」的均势点，**无法从 Human-SL 映射推出 BASE 上调依据**。

建议：

- **`BASE_VISITS_AM1D` 维持 3000（不调整）**。依据：
  1. 社区经验锚点（README 2.3/4.4）：「b10c128 约 1000~2000 visits ≈ 业余 1 段」，
     当前公式 am1d 在 b10c128 = 3000 × factor(0.4) = 1200v ∈ [1000, 2000]，与锚点吻合；
  2. Human-SL 路径本次未能提供任何强度的绝对锚点（见第 4 节），无实测依据上调；
  3. 若产品上希望「1 段更强、更稳」，可主观上调至 3600~4800（1.2~1.6 倍）并重新做 L1 相邻档
     扫描验证——但这属于产品取舍，不是本校准的实测结论。
- **置信度**：对「Human-SL 弱于本地任何档」结论置信度高（3 个 profile × 多等级档 × 9/19 路
  共 50+ 盘全部一致）；对「BASE=3000 正确」置信度中等——依赖社区锚点而非本机实测。
- **后续**：建议走 README 4.4 的可选交叉验证路径（野狐/弈客/星阵平台人工对弈 2~3 个映射点），
  或引入更强的强度标尺（如 KataGo 官方最强权重按固定段位配置对弈）再校准 BASE。
